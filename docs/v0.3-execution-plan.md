## 一、机器分工（2026-08-10 修订）

经实测验证，公司电脑具备完整开发能力（Python 3.12 + torch 2.13 CPU + librosa + pytest 9 全套推理栈可用，eval/ 中 08-06 批量跑分日志即为本机产出；Node 24 + node_modules 齐全，`npm run dev` 验证可跑；93 首 test-audio 与全部 eval 资产在本地）。分工修订为：

| 机器 | 职责 |
|------|------|
| 公司电脑 | 全部开发、测试、eval 批量评估（注意 torch 为 CPU 版，批量跑分较慢） |
| 另一台电脑 | 仅三件事：PyInstaller + electron-builder 打包、装包后自动更新 E2E 验证、发 GitHub Release |

**双机同步纪律（硬规则）**: 任何一台机器开工前必须 `git pull`，收工必须 push。违反此条是 08-07 分叉事故的根因。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| CI 上 Python 依赖过重 | 中 | 最小依赖集 requirements-ci + pip cache；实在不行 CI 先只跑前端三关卡，pytest 后补 |
| 双机再次分叉 | 高 | 硬规则：开工 pull、收工 push；发现分叉立即停手汇报 |
| printToPDF 排版不可控 | 低 | 先出简版模板过验收，美化后置 |
| 本机 CPU 推理慢拖累 B5 | 低 | 批量评估放挂机时段；不阻塞 B1-B3 主线 |
| B1-B3 期间 main 被另一台电脑推打包类提交 | 低 | 功能开发走短命 feature 分支，完成即合，不长期悬挂 |
